LESSON 01.01 / FOUNDATIONS

LLM 如何工作：
从文本到下一个 Token。

AI 杂记 · 2026.11.18 · 基于原书 §1.1 的扩展讲解

模型没有先写好一整段答案再把它慢慢显示出来。对本节讨论的自回归语言模型而言，生成是一个反复发生的过程：根据已有前缀，给出下一 token 的分布，再把选出的 token 接回上下文。

01 / THE MENTAL MODEL

先回答：模型到底在预测什么？

设已有前缀是 x₁, …, xₜ。一次生成步骤要回答的是：在这些 token 条件下，词表中每一个 token 成为下一个 token 的概率有多大？模型输出的是一个分布；解码策略再从中选出具体结果。

pθ(xt+1 ∣ x1:t)θ：模型参数　·　x₁:ₜ：当前前缀　·　xₜ₊₁：待预测的下一 token

一整段文本的概率，可以按链式法则分解为每一步条件概率的乘积。自回归模型把这个分解变成可执行的生成方式。第一项的空前缀可由模型约定的起始标记来表示。

pθ(x1:T) = ∏t=1…T pθ(xt ∣ x<t)整段文本是序列；每一步的条件分布依赖之前已经给定或生成的 token。

本节结束后，你应当能够

  1. 画出 Tokenizer → Embedding → Transformer → LM Head → 解码的路径。
  2. 说明训练位置并行，为什么不等于可以读取未来 token。
  3. 区分参数学习、上下文增长与 KV Cache 复用。
  4. 解释模型生成动作描述，为什么还不等于 Agent 已执行动作。
本节的适用范围主要讲解 decoder-only、自回归文本模型的典型路径。多模态、编码器模型、扩散语言模型等有各自不同的计算与生成方式，不用本节流程概括所有模型。
02 / THE COMPUTATION PATH

一次前向：符号变成表示，再变成分布。

为了看清形状与状态，我们构造一个很小的教学世界：词表只有 8 项，隐藏维度也设为 8。输入是「GPU 正在等待」。这些 token、ID 与数值都是自编示例，不是 Qwen、GPT 或其他真实 tokenizer 的输出。

GPUID = 0正在ID = 1等待ID = 2

文本 → 离散 ID

教学输入被映射为 [0,1,2]，ID 只是词表索引。

[T] = [3]

统一省略 batch 维。教学词表：0 GPU、1 正在、2 等待、3 通信、4 数据、5 计算、6 。、7 <EOS>。真实系统还可能包含特殊 token、位置输入和不同的输出头。

四个阶段，各自解决不同的问题

Tokenizer 负责离散化。Token 可以对应常见词、词片段、单字或字节组合；具体切分取决于 tokenizer。ID 大小没有“更高级的语义”之意。聊天角色标记、工具结果和提示词，最终也需要编码成模型可处理的输入。

Embedding 负责把索引变成可计算的向量。从表 E 中读取第 0、1、2 行，形成输入矩阵 X。Embedding 是模型参数的一部分；一次普通推理只是查表，不会因为读取了这一行就更新这一行。

Transformer 负责上下文加工。注意力、MLP、归一化和残差等模块逐层变换表示。输入 token「等待」的初始向量与经过上下文处理后的隐藏状态，并不是同一个东西；后者包含前缀影响。

LM Head 负责产生词表得分。最后位置的隐藏状态映射成 V 个 logits。Logit 是未归一化分数，可正可负；经 softmax 才成为概率。本节教学模型中 d=V=8 只是方便展示，二者在真实模型中不需要相等。

ht ∈ ℝd　→　z ∈ ℝV　→　p ∈ ΔV−1隐藏状态 → 全词表分数 → 非负且和为 1 的分布。这里以单个生成位置为例。
03 / PARALLEL DOES NOT MEAN BIDIRECTIONAL

所有位置同时算，也不能偷看后面的答案。

训练时，一整个序列可以一次进入 Transformer。并行指的是多个位置的运算能够批量组织；可见性则由 attention mask 决定。对因果自注意力，位置 i 能读取输入中的位置 j≤i，而未来位置 j>i 必须被遮住。

选择左侧 token，观察它能读取的位置CAUSAL MASK / 不是权重热图
行是查询位置，列是被读取的位置。

「等待」只能读取自己与前面的输入。

✓ 允许读取　× 被屏蔽
本图没有表示实际注意力权重。

例如训练输入为「GPU / 正在 / 等待 / 通信」时，「等待」这一位置可以用前面的内容去预测「通信」，但不能直接读取输入中后面的「通信」。否则训练任务会泄漏答案，无法对应推理时的生成条件。

阅读原书时补上的一个限定原书 §1.1 用“读取其他位置”的直觉描述概括 attention；在本课讨论的自回归 decoder 中，应加上因果遮罩这一条件。这个限定直接关系到训练／推理的一致性，不能省略。

此外，hi 对应的是输入位置 i 的上下文状态，通常用来预测位置 i+1 的 token。不要把“读入哪个 token”和“正在预测哪个 token”混为一谈。

04 / FROM LOGITS TO A CHOICE

概率分布不是答案，解码才作出选择。

模型产生得分 z 后，温度 τ 可以改变 softmax 分布的尖锐程度。较低温度通常使分布更集中，较高温度使其更平坦。但无论如何调整，都不会凭空引入缺失证据，也不会自动保证事实正确。

pi = exp(zi/τ) / ∑j exp(zj/τ),　τ > 0贪心解码直接取 argmax，不需要把 τ=0 代入这个公式。

固定教学 logits，依词表顺序为 [−2.3, −1.8, −1.4, 2.8, 2.1, 1.3, 0.5, −0.7]。这是本地计算的完整 8 项教学分布，无模型调用，不是实际性能或质量测量。概率显示四舍五入后可能不恰好加到 100%。

贪心选择概率最大项；随机采样按照分布抽样。Top-k、Top-p 等方法还会筛选候选集合，这些留到后续小节。通常不会希望输出严格复读最高频模式，也不会希望随机性淹没任务约束，因此解码是质量、稳定性和多样性之间的设计选择。

在这个教学分布里「通信」得分最高，只说明我们给它设置了较高的 logit。它完全不能证明某个 GPU 的等待由通信导致。判断事实仍然需要真实上下文、外部证据或验证机制。

05 / PARAMETERS VS CONTEXT

训练改变函数，推理使用函数。

如果把模型写成 fθ，训练是在数据和损失函数的约束下更新 θ；普通推理则在 θ 固定时，把不同上下文输入同一个函数。多轮对话让输入变长，不等于模型在每一轮都重新训练。

切换视角：同一类模型，不同执行方式TEACHER FORCING / AUTOREGRESSION

训练：给定真实前缀，学习预测下一 token

输入与监督标签错开一个位置，再计算下一 token 的预测损失。

input [0,1,2,3] → target [1,2,3,6]

为什么训练可以一次预测多个位置？

训练数据中，完整文本已经给定。我们把真实前缀交给每个位置，并同时计算下一 token 的损失，这称为 teacher forcing。因果遮罩负责阻止未来泄漏；位置并行并没有消除序列的条件关系。

ℒ(θ) = − 1/(T−1) · ∑i=1…T−1 log pθ(xi+1 ∣ x1:i)这是省略 batch 与任务 mask 的下一 token 平均负对数似然示意。实际 SFT 还常只对目标回答位置计损失。
比较项训练（典型 teacher forcing）普通自回归推理
前缀来自哪里训练样本的真实 token用户输入与此前已选出的 token
是否更新 θ通过反向传播与优化器更新通常不更新
预测位置如何组织多个已知位置可并行计算后续新 token 依赖先前的生成结果
运行时状态激活、梯度、优化器状态等上下文、KV Cache、采样状态等

这里说“普通推理通常不更新参数”，是为了留下精确边界：显式的在线训练或测试时参数适配是另外一类方法，不能从“对话在继续”直接推断它们已经发生。

06 / THE RUNTIME VIEW

同一条生成链，分成两个运行阶段。

Prefill 与 Decode 是理解推理性能的入口。Prefill 处理已知的输入前缀，最后位置的输出可以选出第一个新 token。随后，Decode 一步步处理上轮选出的 token，并继续预测下一项。

沿着固定教学序列，走过三次前向KV CACHE / 每层状态的缩略图
本轮预测 → 通信

Prefill 建立前缀缓存，并预测第一个新 token。

此图固定演示「GPU / 正在 / 等待 → 通信 → 。 → <EOS>」，不与上一个随机采样实验联动。Kᵢ、Vᵢ 是位置 i 的缓存缩写；真实 Transformer 通常在每个注意力层维护对应缓存。此处省略头、batch、层数与分页结构。

KV Cache 保存的是已有位置的 Key／Value 等运行时状态，而不是“学到了新知识”的新参数。在因果模型中，给序列追加未来 token 不会改变过去位置的计算结果，因此可以避免反复重算它们的 K/V；新 token 的 Query 仍需访问已有缓存。

“每步一个新 token”也不意味着整张 GPU 只能做一个标量运算。层内矩阵乘法、多个请求的批处理，以及特定推测解码等机制，会影响实际执行。吞吐与延迟由输入长度、输出长度、batch、注意力结构、缓存和硬件共同决定；不能把所有 Prefill 都武断归类为纯计算瓶颈，或把所有 Decode 都认定为同一种瓶颈。

把三个东西彻底分开模型参数 θ：学到的函数。
上下文：本次调用提供的 token 与结构。
KV Cache：为这条输入序列保存、可复用的中间状态。
它们生命周期不同，大小来源不同，优化手段也不同。
07 / FROM A MODEL TO A SYSTEM

模型生成了动作，系统才执行动作。

如果模型输出一段 JSON：{"tool": "read_profile", "run_id": "demo"}，底层仍然是在生成符合上下文的 token。接下来的解析、参数校验、工具调度、结果读取和再次调用模型，属于周围的运行系统。

层次它提供什么训练诊断助手中的对应物
模型从上下文生成候选文本或动作提出“可能存在通信等待”的假设
上下文与检索本次任务所需的信息日志、配置、相关 profile 片段
工具与运行时真正执行分析并返回结果解析 timeline，统计 rank 间的等待
验证与控制检查证据、预算和完成条件对照实验是否支持假设，是否需要继续收集

因此，一个语言上非常流畅的诊断，不应直接当作故障结论。理想的输出要能指出证据、解释替代假设，并给出下一步可验证的检查。这个差异，是后续课程从“模型质量”转向“任务成功”的起点。

今天只建立边界，不提前堆框架你已经能解释单次模型调用的内部过程。第四章才会把它放进有状态执行循环，第七章再讨论如何评估完整任务。先看清组件之间的责任，再决定是否需要 Agent。

09 / TAKE THIS WITH YOU

一个分布，一个循环，三类状态。

  • 一个分布：模型根据前缀产生下一 token 的条件分布。
  • 一个循环：选择 token，接回上下文，直到结束条件满足。
  • 三类状态：模型参数、输入上下文与 KV Cache，各有不同作用。
  • 一条系统边界：生成工具调用描述，不等于工具已经执行成功。

离开课件，做一个一分钟口述

不用看图，解释“用户输入一段 prompt，到屏幕上出现第二个新 token”之间发生了什么。你的解释中，应当同时出现 Tokenizer、最后位置 logits、第一次选择、Prefill、第二次前向与缓存复用。
